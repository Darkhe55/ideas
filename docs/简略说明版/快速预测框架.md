# 快速预测框架（简略说明版）

> 状态：初稿 · 最后更新：2026-11-26
> 关联：[扩展中途版](../扩展中途版/快速预测框架.md) · [最终版](../最终版/快速预测框架.md)

## 一句话

把「预测下一个词」拆成两步：**先猜整句回答会用到哪些词，再只用这些词把句子拼出来**。

## 问题

标准语言模型每生成一个词，都要在全词表 $\mathcal{V}$（约 $10^5$ 个词）上做一次 softmax 并搜索。但一句话真正的回答通常只用到几十个词，剩下 $99.9\%$ 的词在每一步都要参与计算与比较，这是浪费。

## 核心分解

$$
p(y \mid x)\;\approx\;p(C \mid x)\cdot p(y \mid C),\qquad C \subseteq \mathcal{V},\ |C| = k \ll |\mathcal{V}|
$$

- 把输入句子看成一个**词集** $x$（无序、只记存在性）；
- 先由模块一预测一个压缩词表 $C$（“回答可能用到哪些词”），$k$ 通常取 128～1024；
- 再由模块二在 $C$ 内部完成组句（“怎么排这些词”），输出只能落在 $C$ 上。

## 两个模块

### 模块一：词表分布预测

| 项 | 约定 |
| --- | --- |
| 输入 | 输入句子的**词集**，无序数组，只记录词是否存在 |
| 输出 | 全词表上每个词“出现在回答中”的概率 |
| 压缩方式 | 取概率 top-$k$，并强制保留固定闭包（标点、结束符等） |
| 本质 | 从输入得到一个压缩词表 $C$，回答只能从中选词 |
| 关键指标 | 覆盖率：回答真实用词落在 $C$ 中的比例 |

### 模块二：词串生成

| 项 | 约定 |
| --- | --- |
| 输入 | 压缩词表 $C$，以及输入句子的语义表示 |
| 输出 | 由 $C$ 中部分词组成的有序回答 |
| 约束 | 每一步只能从 $C$ 中选词；不要求用上 $C$ 的所有词 |
| 本质 | 在一个 $k$ 维小词表上做自回归生成 |
| 关键指标 | 端到端质量（BLEU / ROUGE / 准确率）与速度 |

## 结构示意

```
输入句子（词集，无序）
        │
        ▼
┌────────────────────┐
│ 模块一 词表分布预测 │  ← 置换不变的编码器 + 全词表 sigmoid
└────────────────────┘
        │ top-k ∪ 闭包
        ▼
   压缩词表 C（|C| = k ≪ |V|）
        │
        ▼
┌────────────────────┐
│ 模块二 词串生成     │  ← 小词表上的自回归解码（选择 + 排序）
└────────────────────┘
        │
        ▼
   回答 y（每个词都来自 C）
```

## 收益与风险

- **收益**：输出层计算从 $O(L \cdot |\mathcal{V}|)$ 降到 $O(|\mathcal{V}|) + O(L \cdot k)$；解码搜索空间从 $|\mathcal{V}|^L$ 降到 $k^L$；模块一每句只跑一次。
- **风险一**：$C$ 覆盖不全时，回答无法表达正确内容 → 需要覆盖率评测与兜底机制。
- **风险二**：无序输入丢失语序 → 语序敏感的输入（否定、指代、主宾颠倒）可能被误读。
- **风险三**：$k$ 越大覆盖率越高、加速越少，需要找到权衡拐点。

## 结论

该框架把“**词表选择**”与“**词序组织**”两个子问题显式解耦：前者一次算完、后者在小空间里做。工程上可解释、可拆分训练；理论上只要覆盖率可控，就是一个无损的分解。
