# 快速预测框架（最终版）

> 阶段：**最终版**（约 20 页） · 状态：**稳定 v1.5** · 最后更新：2026-11-26
> 语言：中文 · [English](../en/final/fast-prediction-framework.md)

## 0. 术语

| 记号 | 含义 |
| --- | --- |
| $\mathcal{V}$ | 全词表，$N = \lvert\mathcal{V}\rvert$，通常 $10^4 \sim 10^5$ |
| $x$ | 输入句子，建模为**词集**（无序，只记存在性） |
| $y$ | 输出回答，有序词序列 |
| $C$ | 压缩词表，$C \subseteq \mathcal{V}$，$\lvert C\rvert = k \ll N$ |
| $T(y)$ | 回答实际用到的词集合 |
| 覆盖率 | $T(y)$ 中落在 $C$ 内的比例 |
| 闭包 $\mathcal{G}$ | 固定保留词集合（标点、EOS 等） |

## 1. 摘要

标准语言模型在每一步都对全词表 $\mathcal{V}$ 做 softmax 并搜索，计算与搜索成本都随 $|\mathcal{V}|$ 线性增长。但真实回答只会用到几十个词。**快速预测框架**（Fast Prediction Framework，FPF）把「预测下一个词」显式拆成两个模块：

1. **词表分布预测**：输入无序词集，输出全词表的存在性概率，取压缩词表 $C$；
2. **词串生成**：只在 $C$ 内部做自回归组句，输出每个词都必须来自 $C$。

分解形式为 $p(y \mid x) = p(C \mid x)\, p(y \mid x, C)$。压缩词表 $C$ 只约束输出：回答只能取 $C$ 中的词；它不限制信息来源——模块二会重读原始输入以获取语序与上下文。当 $C$ 由 $x$ 确定性给出、且 $T(y) \subseteq C$ 时，该分解是**精确的**，质量损失只来自覆盖率不足与模块二的建模误差。

整个框架按序列长度**线性增长**：输入侧与模块二的输入重读都使用线性复杂度机制，不在输入长度上引入 Transformer 式的 $O(n^2)$ 全局注意力；回答内部的自注意力只作用于短回答长度 $L$（2.4）。两个模块各有多种可选实现（第 6、7 章），优化上以三元组一致性为目标（第 8 章）。训练上采用输入端加噪与实时学习（第 9 章），Li-MCTS 的图结构随使用自适应增长（7.2.5）。

## 2. 问题定义

### 2.1 标准目标

$$
p(y \mid x) = \prod_{t=1}^{L} p(y_t \mid x, y_{<t}), \qquad y_t \in \mathcal{V}
$$

每一步需要：

1. 输出层把 $d$ 维隐状态映射到 $N$ 个 logits（$O(N d)$）；
2. 在 $N$ 个候选上做 softmax 与采样/比较；
3. 集束搜索时每步比较 $B \cdot N$ 个候选。

### 2.2 成本结构

| 项 | 标准 LM | 本框架 |
| --- | --- | --- |
| 输出层计算 | $O(L \cdot N \cdot d)$ | $O(N \cdot d) + O(L \cdot k \cdot d)$ |
| 输出 logits 显存 | $O(L \cdot N)$ | $O(N) + O(L \cdot k)$ |
| 每步搜索比较 | $O(B \cdot N)$ | $O(B \cdot k)$ |

以 $N = 10^5$、$k = 512$、$L = 32$、$d = 256$ 估算，输出层乘加次数从约 $8.2 \times 10^8$ 降到约 $3.0 \times 10^7$，约 **27 倍**。$k$ 取 256 时约 30 倍。

以上只计输出层；全局自注意力带来的 $O(n^2)$ 输入侧开销另计，并被 2.4 的设计原则禁止。

### 2.3 关键观察

回答的支撑集 $T(y)$ 很小，且主要由输入决定：

- 对话中，回答用词大多来自输入已出现的词（copy 通道）；
- 改写/摘要中，内容词由输入的语义决定；
- 功能词与标点几乎固定（闭包通道）。

因此“哪些词可能出现”可以**一次算完**，而“怎么排”才是真正的语言建模难题。

### 2.4 设计原则：复杂度线性增长

框架的计算复杂度必须随序列长度 $n$ 线性增长，而不是 Transformer 自注意力那样的 $O(n^2)$ 增长。

- **模块一**：对输入做一次线性扫描——逐词变换（token MLP 或线性注意力）加掩码池化，复杂度 $O(n d^2)$，不做输入内部的两两注意力；
- **模块二**：重读输入长序列（语序与上下文都要），但必须使用线性复杂度编码器（线性注意力、状态空间模型、滑动窗口等）；解码在 $C$ 与短回答长度 $L$ 上工作；
- **可选算法同样受约束**：任何使用全局注意力的组件（如 BERT 双向编码、长回答的 Transformer 解码器）都必须限定在短序列上，或改用线性注意力 / 折叠结构，否则不得作为默认实现。

理由：输入可能是长文档、检索片段或多轮对话。二次复杂度会让代价随输入长度爆炸，抵消词表压缩带来的收益。

## 3. 形式化

### 3.1 分解

$$
p(y \mid x) = p(C \mid x) \cdot p(y \mid x, C)
$$

- $C = \operatorname{TopK}_k\big(\sigma(f_\theta(x))\big) \cup \mathcal{G}$，即 $C$ 是 $x$ 的确定性函数 $C(x)$；
- 模块二以完整输入 $x$ 与 $C$ 为条件，建模 $q_\phi(y \mid x, C) \approx p(y \mid x, C)$。$C$ 只限制输出词表，不限制信息来源。

### 3.2 精确性条件

因为 $C(x)$ 是 $x$ 的确定性函数，且模块二重读完整输入 $x$，条件化不引入新信息：

$$
p(y \mid x, C(x)) = p(y \mid x)
$$

对任意满足 $T(y) \subseteq C(x)$ 的 $y$ 成立。因此：

> **框架的误差 = 覆盖率不足导致的不可表达误差 + 模块二的建模误差。**

$C$ 只是输出侧的白名单，不承担信息瓶颈的角色；没有额外的压缩损失。代价来自覆盖率：回答用词落在 $C$ 外时无法表达。这一代价由覆盖率指标和三元组一致性（第 8 章）显式度量。

### 3.3 目标函数

$$
\mathcal{L} = \mathcal{L}_{\text{cov}} + \lambda\, \mathcal{L}_{\text{gen}}
$$

$$
\mathcal{L}_{\text{cov}} = -\frac{1}{N}\sum_{v \in \mathcal{V}} w_v\Big[z_v \log p_v + (1-z_v)\log(1-p_v)\Big],\quad z_v = \mathbb{1}[v \in T(y)]
$$

$$
\mathcal{L}_{\text{gen}} = -\sum_{t=1}^{L} \log q_\phi(y_t \mid x, y_{<t}, C)
$$

其中 $w_v = \alpha$（正例）或 $1$（负例）。两模块可分别训练（$\lambda$ 阶段化），也可联合微调。

## 4. 模块一：词表分布预测

### 4.1 接口

```
输入  X: 词 id 集合（无序、去重），并附 mask
输出  s: R^N，p_v = sigmoid(s_v)
选词  C = TopK_k(p) ∪ G        # 可选 copy 见 4.4
```

设计约束：

- **置换不变**：输入顺序任意打乱，输出不变；
- **多标签**：每个词独立判断存在性，不是互斥 softmax；
- **一次前向**：整句只跑一次，不逐词调用。

### 4.2 结构

```
X（词集）
  │  Embedding（共享词表）
  ▼
逐词线性变换（token MLP，逐位置独立）
  │  掩码均值池化（置换不变）
  ▼
h ∈ R^d
  │  Linear(d, N)
  ▼
p ∈ [0,1]^N
```

编码器刻意做成**线性**的：每个词独立过一个小 MLP，再掩码均值池化，不做词与词之间的注意力。复杂度随输入长度 $O(n d^2)$ 线性增长，符合 2.4；又因为池化，输出对词序不变，符合“只记词存在性”的约定。若需要更强的词间交互，可用线性注意力（仍是 $O(n)$），但不得引入全局 $O(n^2)$ 注意力。

### 4.3 训练

- 目标集合：$z_v = \mathbb{1}[v \in T(y)]$，回答中重复词只算一次；
- 正负样本极不均衡（正例占比约 $L/N \approx 0.03\%$），必须加权或使用 focal loss；
- 难负例：对与输入高度相关但未出现在回答中的词（如同义候选、同主题词）加大惩罚；
- 选 checkpoint：以 Recall@$k$ 与整句覆盖率为准，而不是 BCE 值。

### 4.4 候选词表构造

$$
C = \operatorname{TopK}_k(p) \cup \mathcal{G}
$$

- $\mathcal{G}$：标点、EOS、UNK、数字占位符；可选高频虚词；
- **copy 通道（可选）**：仅在全序列预测（6.1.2）下把输入词 $X$ 并入 $C$；增量预测（6.1.1）不启用，避免把输入词混进“回答内容词”的标签；
- 阈值补充（可选）：$p_v > \tau$ 的词也纳入，用少量速度换覆盖率；
- 批处理时按 batch 内最大 $|C|$ 补齐到 $k_{\max}$，配合 `cand_mask`。

### 4.5 关键代码

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class VocabularyDistributionPredictor(nn.Module):
    """模块一：词表分布预测。

    输入：无序词集 X（去重后的词 id 数组）
    输出：全词表 logits，p_v = sigmoid(logit_v)

    线性复杂度：逐词变换 + 掩码池化 O(n d^2)，没有输入内部的注意力。
    """

    def __init__(self, vocab_size: int, d_model: int = 256):
        super().__init__()
        self.emb = nn.Embedding(vocab_size, d_model, padding_idx=0)
        # 逐位置独立的小 MLP：对 n 是线性的
        self.token_mlp = nn.Sequential(
            nn.Linear(d_model, 4 * d_model), nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )
        self.classifier = nn.Linear(d_model, vocab_size)

    def forward(self, x_ids: torch.Tensor, x_mask: torch.Tensor) -> torch.Tensor:
        # x_ids: [B, n]；x_mask: [B, n]，1 表示真实词
        h = self.token_mlp(self.emb(x_ids))                 # [B, n, d]
        pooled = (h * x_mask.unsqueeze(-1)).sum(1) / x_mask.sum(1, keepdim=True)
        return self.classifier(pooled)                      # [B, N]
```

```python
def coverage_loss(logits, y_ids, pad_id=0, pos_weight=8.0):
    """模块一损失：多标签 BCE，目标集合 = 回答词集合（重复词只算一次）。"""
    target = torch.zeros_like(logits).scatter_(1, y_ids, 1.0)
    target[y_ids == pad_id] = 0.0
    weight = torch.where(target > 0, pos_weight, 1.0)
    return F.binary_cross_entropy_with_logits(logits, target, weight=weight)
```

```python
@torch.no_grad()
def select_candidates(logits, k, closure, extra_ids=None, pad_id=0):
    """构造压缩词表：TopK ∪ 闭包（全序列模式下可选并入输入词 copy）。返回变长候选列表。"""
    B, N = logits.shape
    k = min(k, N)
    top = logits.topk(k, dim=-1).indices.tolist()          # [B][k]
    out = []
    for b in range(B):
        cand = set(top[b]) | set(closure.tolist())
        if extra_ids is not None:
            cand |= {t for t in extra_ids[b].tolist() if t != pad_id}
        out.append(sorted(cand))
    return out                                             # [B][k_i]
```

> 实现说明：不同样本的 $|C|$ 不同，`collate` 时按 batch 内最大长度补齐，同时产出 `cand_ids` 与 `cand_mask`。`extra_ids` 为补齐后的输入词 id（含输入去重集），仅在全序列预测时传入。

### 4.6 指标

- **Recall@k**：$\mathbb{E}\big[|T(y) \cap C| / |T(y)|\big]$，token 级；
- **FullCoverageRate**：$\mathbb{P}[T(y) \subseteq C]$，整句全覆盖比例，决定端到端上限；
- 覆盖率随 $k$ 的曲线，以及与 $k$ 造成的加速比之间的权衡。

## 5. 模块二：词串生成

### 5.1 接口

```
输入  x: 输入句子（有序，长序列，用线性复杂度编码器处理）
      C: 压缩词表 + cand_mask（输出侧白名单）
输出  y = (y_1..y_L)，每个 y_t ∈ C，不要求用完 C
```

> $C$ 只约束输出：回答的每个词都必须来自 $C$；它不限制信息来源。模块二重读有序输入以获得语序与上下文，补上模块一集合化时丢掉的信息（“A 打 B”与“B 打 A”词集相同，靠重读输入消歧）。重读必须走线性复杂度路径（2.4），不能使用 $O(n^2)$ 全局注意力。

### 5.2 结构

```
x（有序，长序列）
  │  线性复杂度编码器（线性注意力 / SSM / 窗口聚合）
  ▼
mem ∈ R^{n×d}
  │
  ▼
Decoder（交叉注意力 mem；自注意力只在回答长度 L 内）
  │  h_t
  ▼
logits = h_t · E^T   （共享词嵌入）
  │  gather 到 C 的候选下标
  ▼
softmax over k → y_t
```

输出层不再投影到 $N$，而是从共享嵌入矩阵中 gather 出 $C$ 对应的行，softmax 只在 $k$ 个候选上做。批处理时用 `cand_mask` 把 pad 位置置为 $-\infty$。

复杂度：输入编码 $O(n d^2)$（线性），解码交叉注意力 $O(L \cdot n \cdot d)$（对 $n$ 线性），回答自注意力 $O(L^2)$（$L$ 是短回答）。整体对输入长度线性；禁止的是输入编码器里的全局 $O(n^2)$ 自注意力。

### 5.3 约束解码

$$
q(y_t = v \mid \cdot) = \operatorname{softmax}_{v \in C}\big(h_t^\top e_v\big)
$$

- 贪心：每步取 $C$ 内得分最高者；
- 集束：每步保留 $B$ 条前缀，候选扩展集为 $C$，比较量 $O(Bk)$；
- EOS 必须在 $C$ 中（放入闭包 $\mathcal{G}$）；
- 输出长度上限 $L_{\max}$ 与重复惩罚同常规解码。

### 5.4 关键代码

```python
class WordStringGenerator(nn.Module):
    """模块二：词串生成。

    条件：有序输入 x 经线性编码器得到的 mem + 压缩词表 C（C 只约束输出）。
    输出：只能落在 C 上的词串；softmax 维度 = |C| 而非 |V|。
    """

    def __init__(self, vocab_size: int, d_model: int = 256, n_layers: int = 4):
        super().__init__()
        self.emb = nn.Embedding(vocab_size, d_model, padding_idx=0)
        layer = nn.TransformerDecoderLayer(
            d_model, nhead=4, dim_feedforward=4 * d_model,
            batch_first=True, norm_first=True,
        )
        self.decoder = nn.TransformerDecoder(layer, n_layers)

    def forward(self, y_in, mem, cand_ids, cand_mask=None):
        # y_in: [B, L]；mem: [B, n, d]（线性编码器输出）；cand_ids: [B, k]；cand_mask: [B, k]
        h = self.decoder(self.emb(y_in), mem)                 # [B, L, d]
        logits = h @ self.emb.weight.T                        # [B, L, N]，共享嵌入
        logits = logits.gather(2, cand_ids.unsqueeze(1).expand(-1, h.size(1), -1))
        if cand_mask is not None:                             # pad 候选置 -inf
            logits = logits.masked_fill(~cand_mask.bool().unsqueeze(1), float("-inf"))
        return logits                                         # [B, L, k]
```

```python
@torch.no_grad()
def constrained_decode(model, mem, cand_ids, cand_mask, bos_id, eos_id, max_len=64):
    """约束解码：每一步只在候选词表 C 内搜索。"""
    cand = cand_ids[0].tolist()
    ys = torch.tensor([[bos_id]])
    for _ in range(max_len):
        logits = model(ys, mem, cand_ids, cand_mask)[0, -1]   # [k]
        nxt = int(cand[int(logits.argmax())])
        ys = torch.cat([ys, torch.tensor([[nxt]])], dim=1)
        if nxt == eos_id:
            break
    return ys
```

> 集束搜索接口相同，仅把“取 argmax”换成“维护 $B$ 条得分最高的前缀”。

### 5.5 训练要点

- **目标**：teacher-forcing 交叉熵，只在 $C$ 上归一化；
- **候选噪声**：训练时对 gold 集合随机丢弃 10%～20%、加入少量干扰词，模拟模块一的漏词与多词；
- **两段式可选变体**：先由选择头预测子集 $S \subseteq C$（sigmoid 多标签），再由排序解码器排 $S$。直接自回归已能隐式完成“不必用全词”，两段式仅在长答案场景下作为备选；
- **联合微调**：对 $\operatorname{TopK}$ 使用 straight-through / Gumbel-softmax 估计器，让模块二的序列损失回传到模块一。

### 5.6 指标

- 端到端：BLEU / ROUGE / 任务准确率，与同参数量全词表基线对比；
- 受限困惑度：只在 $C$ 上计算，衡量模块二自身拟合；
- 速度：每句延迟、tokens/s、显存峰值。

## 6. 模块一可用算法

模块一的本质是“从输入预测一个词集合”。选型可以拆成两个正交的维度：

- **预测什么**：增量预测 / 全序列预测 / 抗干扰预测；
- **用什么模型**：MLP / BERT 采样 / 流匹配。

两者可自由组合，例如「MLP + 增量预测」追求极限速度，「BERT 编码 + 抗干扰预测」追求噪声输入下的鲁棒性。

### 6.1 三种预测方式

对训练样本 $(x, y)$，记 $T(\cdot)$ 为词集合。三种方式的区别只在于**标签集合 $Z(x, y)$** 的定义：

| 方式 | 标签集合 $Z(x, y)$ | $C$ 的构成 | 特点 |
| --- | --- | --- | --- |
| 增量预测 | $T_{\text{content}}(y)$：回答中的内容词 | $Z \cup \mathcal{G}$ | $k$ 最小，正样本密度最高 |
| 全序列预测 | $T(x) \cup T(y)$ | $Z$ | 输入词覆盖由构造保证，copy 自然 |
| 抗干扰预测 | $\big(T(x) \cup T(y)\big) \setminus N(x)$ | $Z$ | 噪声输入下 $C$ 仍紧凑 |

#### 6.1.1 增量预测

只预测回答里“可以包含的词”，即实词/内容词（名词、动词、形容词等）；功能词（的、了、是）与标点由固定闭包 $\mathcal{G}$ 提供。

- 训练目标：$z_v = \mathbb{1}[v \in T_{\text{content}}(y)]$；
- 候选：$C = \operatorname{TopK}_k(p) \cup \mathcal{G}$；
- 优点：$|C|$ 小（通常 64～256）、正样本比例高、训练稳定；
- 难点：内容词与功能词的边界依赖分词与词性；闭包必须覆盖全部功能词，否则回答会缺少语法骨架；
- 适用：短回答、对话、意图明确的任务。

#### 6.1.2 全序列预测

标签集合是输入词集合与回答词集合的并集：$Z = T(x) \cup T(y)$。

- 语义上即“从输入到输出的全部词汇都包含在压缩词表中”；
- 输入词自动进入 $C$（copy 通道），回答复用输入词时覆盖率天然成立；
- 难点：$|C|$ 随输入长度增长；长文档、检索片段里大量停用词占用预算；极端情况下退化为“全词表”，加速失效；
- 适用：改写、摘要、抽取式问答等 copy 密集场景。

#### 6.1.3 抗干扰预测

把输入中的一部分词视为噪声 $N(x)$，标签集合为去噪后的并集：

$$
Z = \big(T(x) \cup T(y)\big) \setminus N(x)
$$

模型需要学会“删掉没用的输入词、保留有用的词”，输出一个**去噪后的全序列词表**：既包含回答用词，也包含应当保留的输入词，但不含噪声词。

噪声标签的来源：

1. **合成噪声**：训练时向输入随机插入无关词或句子，并记录插入位置，作为噪声标签；
2. **启发式噪声**：停用词、与回答无共现的孤立词、与回答语义无关的片段；
3. **学习式噪声**：用一个小打分器估计每个输入词对回答的贡献，低于阈值的判为噪声。

- 优点：长文档、检索片段、闲聊噪声等场景下，$|C|$ 不随输入膨胀；
- 难点：误删关键词会直接导致覆盖率失败；噪声标签本身可能不准，需要「覆盖率 + 去噪」联合监督；
- 与全序列的关系：全序列预测是 $N(x) = \varnothing$ 时的特例。

#### 6.1.4 三种方式对比

| 维度 | 增量预测 | 全序列预测 | 抗干扰预测 |
| --- | --- | --- | --- |
| $k$ 规模 | 最小 | 随输入增长 | 中等、可控 |
| 覆盖难度 | 中（只预测内容词） | 低（copy 保证） | 高（可能误删） |
| 额外监督 | 无 | 无 | 需要噪声标签或打分器 |
| 主要风险 | 闭包不全 | 速度收益被输入长度吃掉 | 误删关键词 |
| 推荐场景 | 对话、短答 | 改写、摘要、抽取 | 长文、检索增强、噪声输入 |

### 6.2 三种模型族

#### 6.2.1 MLP：最简单的主干

把输入词嵌入做求和/平均（也可以直接用 TF-IDF 稀疏向量），过 2～3 层 MLP 输出 $N$ 维 logits：

$$
\bar{e} = \frac{1}{n}\sum_{i=1}^{n} E[x_i],\qquad
s = W_2\,\sigma(W_1 \bar{e} + b_1) + b_2 \in \mathbb{R}^{N}
$$

- 复杂度：每样本 $O(n d + d^2 + N d)$，其中 $N d$ 是输出层，无法避免；
- 优点：实现简单、训练稳、推理快，是覆盖率的下界基线；
- 缺点：没有词间交互（“不”与“好”组合的语义丢失），组合泛化弱；
- 增强：低秩输出层（$W = UV^\top$，$U \in \mathbb{R}^{N \times r}$、$V \in \mathbb{R}^{d \times r}$）、特征哈希、分层 softmax。

MLP 足够好的前提是：集合主要由输入词频与主题决定（对话、模板化任务）。对语义组合要求高的任务，需要上下文模型。

#### 6.2.2 BERT 采样：双向编码 + 迭代集合采样

用 BERT 类双向编码器（Devlin et al., 2019）得到上下文表示，再生成集合。按采样粒度分三档：

1. **逐词打分（边缘近似）**：MLM 头对词表打分取 top-$k$。等价于「BERT 表征 + sigmoid 头」，但每个词独立判断，集合内部依赖不建模。
2. **迭代采样（MaskGIT 式；Chang et al., 2022）**：从空集或全掩码出发，重复 $T$ 轮：
   - 每轮预测每个候选词的存在概率；
   - 保留置信度最高的一批词，其余保持“未定”；
   - 下一轮以已确定词为条件继续预测。
   通常 $T = 4 \sim 8$ 轮。优点是集合级依赖与多样性更好、$k$ 可控；缺点是采样推理有随机性。
3. **Gibbs 采样**：固定集合中其余词，逐位置重采样，精细但很慢。

训练信号：随机掩码输入做去噪训练；或在多标签 BCE 之外增加「集合重建」目标——给定部分词，预测剩余词。

- 优点：上下文建模强、可直接复用预训练权重；
- 缺点：迭代采样成本是 $T$ 次前向；结果不保证最优；阈值与轮数需要在验证集上校准；
- 复杂度：BERT 双向编码是全局注意力，$O(n^2)$，与 2.4 冲突；只适合短输入，或替换为线性注意力变体，作为研究选项而非默认。

#### 6.2.3 流匹配：把集合当作连续分布来生成

前两种方法输出的是每个词的边缘概率。若希望**采样得到整个集合**、保留“同一输入有多种合理词集”的多峰性，可以用流匹配（Flow Matching；Lipman et al., 2023）直接建模集合分布。

设目标集合的存在性向量 $z \in \{0,1\}^N$（或 logit 空间中的 $z \in \mathbb{R}^N$），噪声 $z_0 \sim \mathcal{N}(0, I)$，数据 $z_1 \sim p_{\text{data}}(\cdot \mid x)$。定义线性插值路径

$$
z_t = (1 - t)\, z_0 + t\, z_1,\qquad t \in [0, 1]
$$

速度场 $v_\theta(z_t, t, x)$ 回归 $\mathrm{d}z_t/\mathrm{d}t = z_1 - z_0$，损失为

$$
\mathcal{L}_{\text{FM}} = \mathbb{E}_{t,\, z_0,\, z_1}\Big[\big\| v_\theta(z_t, t, x) - (z_1 - z_0) \big\|^2\Big]
$$

推理时从 $z_0$ 出发积分 ODE（Euler 或 RK4，$T$ 步），得到 $z_1$，再取 top-$k$ 或阈值得到 $C$。

关键工程问题：

- **维度灾难**：$N$ 可达 $10^5$，直接在 $N$ 维做流代价过高。可行方案是低秩流（在 $r = 64 \sim 256$ 维潜空间积分，再线性解码到 $N$）或 shortlist 流（先用便宜的 MLP 取 $512 \sim 2048$ 候选，只在候选上做流）；
- **离散输出**：连续 $z$ 需阈值化或取 top-$k$ 离散化，阈值用验证集校准；
- **置换不变**：速度场不能带位置编码，否则破坏集合的无序性；
- **耦合**：$z_0$ 与 $z_1$ 的配对方式影响收敛，可用最优传输（OT）耦合代替独立采样。

- 优点：显式生成式建模，多样性好，不受 BCE“平均化”影响；
- 缺点：ODE 积分慢、实现复杂、离散化有偏；更适合作为质量上限的研究路线，而非 v1 的默认选择。

#### 6.2.4 选型建议

| 目标 | 推荐组合 |
| --- | --- |
| 最快、够用 | MLP + 增量预测 |
| 覆盖优先、copy 密集 | BERT 编码 + 全序列预测 |
| 长文/噪声输入 | BERT 编码 + 抗干扰预测 |
| 质量上限研究 | 流匹配（低秩或 shortlist） |

## 7. 模块二可用算法

模块二在压缩词表 $C$ 上生成有序词串，两条路线：

- **神经自回归**：Transformer 解码器（输入走线性复杂度编码器，回答限定在短长度），工程成熟、质量稳定；
- **结构化搜索**：李-蒙特卡洛树（Li-MCTS），可解释、参数效率可能更高，但训练与推理更复杂。

### 7.1 Transformer 解码器

基础结构已在 5.2 给出，这里补充可选变体：

| 变体 | 说明 |
| --- | --- |
| 线性编码 + 交叉注意力（默认） | 输入用线性复杂度编码器（线性注意力 / SSM / 窗口聚合），解码器对 mem 做交叉注意力 |
| 线性注意力解码器 | 回答内部用线性注意力，保持 $O(L)$；输入仍走线性编码器 |
| 共享词嵌入 | 输出层复用输入嵌入，gather 候选行，省参数 |
| 分层词表 | 高频词与内容词分组，进一步降低 softmax 成本 |
| 前缀树约束 | 词表是子词时，用 trie 只在合法前缀上展开 |

- 优点：并行训练、生态成熟、与现有 LM 兼容；
- 缺点：解码串行；标准自注意力在回答上是 $O(L^2)$，长回答需换线性注意力，否则违反 2.4。

### 7.2 李-蒙特卡洛树算法（Li-MCTS）

#### 7.2.1 设计哲学

把“组句”看作在**二元运算函数有向图**上的折叠计算：

- 图的每个节点 $v \in V_G$ 是一个可学习的二元算子 $f_v(a, b): \mathbb{R}^d \times \mathbb{R}^d \to \mathbb{R}^d$；
- 节点的每条出边 $e = (v, u)$ 绑定一个**值域分割区域** $R_e \subseteq \operatorname{range}(f_v)$；
- 函数 $f_v$ 计算完成后，根据输出值落入哪条边的区域，路由到下一个节点 $u$；
- 边权就是分割边界，可学习（标量分位数，或嵌入空间中的超平面）。

一句话：**节点是算子，边是值域的分段，路径是数据相关的程序。**

#### 7.2.2 序列折叠

按顺序逐个读取元素 $x_1, x_2, \dots, x_n$（元素可以是输入词，也可以是候选词）：

- **初始**：$s_2 = f_{\text{init}}(e_{x_1}, e_{x_2})$，节点取 $\operatorname{Route}(\text{init}, s_2)$；若序列只有一个元素，则 $s_1 = f_1(e_{x_1})$；
- **递推**（$t \ge 3$）：

$$
s_t = f_{node_t}\big(s_{t-1},\, e_{x_t}\big),\qquad
node_{t+1} = \operatorname{Route}(node_t,\, s_t)
$$

- **读出**：末状态 $s_n$（或每步 $s_t$）经线性读出层映射到 $C$ 上的分布，或输出一个标量得分。

其中 $\operatorname{Route}(v, s)$ 返回 $s$ 落入的出边所指向的目标节点；值域分割可用标量分位数，也可用可学习的超平面。折叠每步只做一个二元算子（$O(d^2)$），对序列长度线性增长，没有全局注意力，天然符合 2.4。

#### 7.2.3 为什么需要蒙特卡洛树搜索

- 路由是离散的（区域 → 节点），不可导；
- 可能的路径/词序组合数巨大（$C$ 的子集 × 排列）；
- 目标往往是序列级的（整句质量），而不是逐词局部最优。

MCTS 提供前向模拟评估、UCT 平衡探索，且无需可微即可优化序列级目标（Kocsis & Szepesvári, 2006; Silver et al., 2018）。树的每个节点维护访问次数 $N$ 与累计收益 $W$：

$$
\text{UCT} = \frac{W}{N} + c\sqrt{\frac{\ln N_{\text{parent}}}{N}}
$$

流程：选择（Select）→ 扩展（Expand）→ 模拟（Simulate）→ 回传（Backpropagate）。

```text
状态：已选词序列 + 当前图节点 + 折叠状态 s
动作：从 C 中选下一个词（或选择出边/算子）
模拟：用快速策略（贪心折叠）补全序列并打分
终局：读出层给出序列得分，或与目标分布的一致性
```

#### 7.2.4 训练方式

| 方案 | 思路 | 难度 |
| --- | --- | --- |
| 可微松弛 | 值域分割用 softmax 软路由 + 温度退火，算子端到端训练 | 中 |
| Straight-through | 前向硬路由，反向用软路由梯度 | 中 |
| 强化学习 | 硬路由，用 REINFORCE / 策略梯度更新路由决策 | 高 |
| 两阶段 | 先以 gold 序列做 teacher-forcing 折叠（监督），再用 MCTS 微调 | 高 |

图结构可以人工设计（少量算子：加、乘、门控、小 MLP），也可以用神经架构搜索自动发现。

#### 7.2.5 图结构的自适应增长

节点与边不是训练前固定死的，而是在训练与运行中按使用情况动态生长：

- **从小图开始**：初始图可以很小（例如只有初始函数与少量节点），节点与边按需添加；
- **热点出度扩张**：统计每个节点的函数被调用次数、每条边的命中次数；节点使用得越多，其出度越大——把值域切得更细、增加分支，让高频路径表达更精细；
- **随机新增连接**：需要扩展时，以一定概率把新边接到已有节点（复用已学好的子图），以一定概率创建新节点（开辟新分支）；
- **容量约束**：单节点出度上限、总边数预算；低使用率的边定期剪枝，避免图无限膨胀；
- **分裂策略**：出度扩张时优先在样本密集的值域区间上分裂，保证新分支有足够的训练信号。

这套机制让图容量随数据分布自动扩展：热门区域更精细，冷门区域保持稀疏。它也是实时学习（9.3）在结构层面的体现。

#### 7.2.6 优缺点

- 优点：
  - 计算图共享，参数效率可能高于同容量 Transformer；
  - 值域路由是分段函数，路径可解释（类似决策树/自动机）；
  - 推理时可依据值域剪枝，跳转到相关子图。
- 缺点：
  - 图结构与路由的联合优化困难；
  - MCTS 推理需要大量模拟，延迟高于自回归；
  - 折叠本质串行，难以 GPU 并行；
  - 长序列误差累积，路由抖动可能导致路径不稳定。

#### 7.2.7 与 Transformer 的对比

| 维度 | Transformer | 李-MCTS |
| --- | --- | --- |
| 训练并行 | 高 | 低（折叠串行） |
| 路由/结构 | 连续注意力 | 离散值域路由 |
| 可解释性 | 中 | 较高 |
| 推理延迟 | 每步 $O(kd)$ | 每步 $O(d^2)$ + MCTS 模拟 |
| 工程成熟度 | 高 | 低（研究型） |
| 适合场景 | 通用生成 | 强结构、可解释、小模型场景 |

## 8. 优化目标：三元组一致性

### 8.1 三个要素

对样本 $(x, y)$：

- $A = T(y)$：训练数据给出的后续内容词集；
- $B = T(\hat{y})$：词串生成实际输出的词集；
- $C = C(x)$：压缩词表。

三条约束构成一个闭环：

1. **覆盖**：$A \subseteq C$ —— 后续内容必须被包含在压缩词表中；
2. **生成一致**：$B \approx A$ —— 词串预测必须与后续内容一致；
3. **包含**：$B \subseteq C$ —— 词串预测必须包含于压缩词表。

第 3 条在约束解码下由构造保证（$B$ 只能取自 $C$）；真正需要优化的是第 1、2 条及其相互牵制。

### 8.2 为什么必须是三元组

单独看每一条都可以被“作弊”：

| 只优化 | 作弊方式 | 后果 |
| --- | --- | --- |
| 覆盖 $A \subseteq C$ | 令 $C = \mathcal{V}$ | 覆盖率 100%，加速归零 |
| 生成一致 $B \approx A$ | 忽略 $C$，退回普通 LM | 框架失去意义 |
| 包含 $B \subseteq C$ | 令 $C$ 极大，或输出空序列 | 约束平凡成立，质量崩溃 |

三者联合，再加上对 $|C|$ 的预算约束，才能保证学到的不是平凡解。这与循环一致性（cycle consistency）的思想同源：让三个量互相印证，而不是各自独立优化。

### 8.3 形式化

- 覆盖率约束：$\mathbb{E}[v_1] \le \varepsilon_1$，其中 $v_1 = \mathbb{1}[A \not\subseteq C]$；
- 生成一致性：$\mathcal{L}_{\text{gen}} = -\log q(y \mid x, C)$（teacher forcing），或序列相似度 $s(B, A) \ge \tau$；
- 包含约束：$v_3 = \mathbb{1}[B \not\subseteq C] \equiv 0$（硬掩码）；
- 容量约束：$|C| \le k$。

总目标：

$$
\mathcal{L} = \mathcal{L}_{\text{gen}} + \lambda\,\mathcal{L}_{\text{cov}} + \mu\,\frac{|C|}{k} + \nu\, V_{\text{gen}},
\qquad V_{\text{gen}} = 1 - s(B, A)
$$

优化形式（约束优化视角）：

$$
\min\ \mathcal{L}_{\text{gen}} + \mu\, \mathbb{E}\frac{|C|}{k}
\quad \text{s.t.}\quad
\Pr[A \subseteq C] \ge 1 - \varepsilon_1,\ \
\Pr[s(B, A) \ge \tau] \ge 1 - \varepsilon_2,\ \
B \subseteq C
$$

工程上更常用惩罚形式：覆盖率不足时加罚，$|C|$ 超预算时加罚；$\lambda, \mu, \nu$ 用验证集调，或作为拉格朗日乘子自适应更新。

### 8.4 训练策略

- **交替优化（硬 EM 风格）**：
  - E 步：固定生成器，更新模块一，在「覆盖率 $\ge 1 - \varepsilon_1$」的约束下最小化 $|C|$；
  - M 步：固定模块一，更新模块二，最大化 $\log q(y \mid x, C)$。
- **端到端**：用 straight-through top-$k$ / Gumbel-softmax 让序列损失回传模块一，联合训练；
- **课程**：先在 gold $C$ 上把模块二训到接近上限（保证第 2 条不被第 1 条拖累），再切换到预测 $C$；
- **拉格朗日乘子**：把覆盖率约束变成可自适应调整的 $\lambda$，避免手工调参。

### 8.5 指标

- **三元组一致率**：$R = \Pr\big[v_1 = 0 \wedge s(B, A) \ge \tau \wedge v_3 = 0\big]$；
- 覆盖率（Recall@$k$ / FullCoverageRate）；
- 生成质量（BLEU / ROUGE / EM）；
- $|C|$ 均值与推理速度。

三元组一致率是这套框架最贴切的单一指标：它同时要求「词表够用」「生成的句子对」「生成的词都在词表里」。

## 9. 训练流程

### 9.1 分阶段流程

```
阶段 0  数据构造
        x → 去重词集；y → 词序列；统计 T(y) 大小分布
阶段 1  模块一
        多标签 BCE，正样本加权；按 Recall@k / 覆盖率选模型
阶段 2  模块二（gold C）
        交叉熵 + 候选噪声；此阶段得到质量上限
阶段 3  模块二（预测 C）
        冻结模块一，用其输出的 C 继续训练（自蒸馏）
阶段 4  可选联合微调
        straight-through top-k + 序列损失；小学习率
```

顺序训练的理由：模块二若一开始就面对模块一的预测集合，会因为随机漏词学到“补偿策略”，掩盖模块一的覆盖率问题；先 gold 后预测，便于分别定位两类误差。

### 9.2 输入端加噪

训练输入不是始终干净的。具体做法：

- 在输入序列的**随机位置插入随机噪声词**（从词表随机采样，或从专门的噪声池采样）；
- 插入概率随位置递增：**越靠近句子末端，噪声越密**；
- 噪声比例按课程调度，从 0 逐步升高到目标水平（如 10%～20%）。

设计理由：

1. 让两个模块见过“多余词”，学会忽略噪声并保持覆盖率，与抗干扰预测（6.1.3）天然配套；
2. 生成紧接在输入末端开始，末端噪声对第一个输出词的干扰最大，需要更密集的训练信号来锻炼鲁棒性（这一位置偏好是待验证的设计假设）；
3. 加噪等价于数据增强，缓解小数据下的过拟合。

实现要点：

- 噪声词不应与答案用词重合，避免污染覆盖标签；
- 每个样本记录插入噪声的位置，供抗干扰预测使用；
- 只在训练时加噪，推理输入保持干净。

### 9.3 实时学习

训练哲学：模型不应只在初始阶段做一次统一的大规模训练后就冻结；它应随着新数据**持续、实时地更新**。

- **在线更新**：新样本到达即做小步更新（小学习率；需要时配合 EWC 等正则）；
- **回放缓冲**：保留少量旧样本，缓解灾难性遗忘；
- **结构自适应**：图结构、候选词统计随使用增长（见 7.2.5）；
- **监控与回滚**：在线指标持续监控，退化时回滚到上一检查点；
- **与离线训练的分工**：离线的大规模训练提供初始态与稳定的基础分布，实时学习负责持续适配新分布。

风险：灾难性遗忘、在线噪声数据污染、评估滞后。对策：回放 + 小学习率 + 定期全量刷新 + 数据质量过滤。

## 10. 推理与复杂度

```
输入 x
  ├─ 模块一（一次线性前向）
  ▼
s ∈ R^N → C（TopK + 闭包，可选 copy）   ← 只约束输出
  │
  ▼
模块二（重读输入 x，线性编码；自回归，词表 = C）
  ▼
回答 y
```

- 对输入长度线性：模块一 $O(n d^2)$，模块二输入编码 $O(n d^2)$ + 解码交叉注意力 $O(L \cdot n \cdot d)$；
- 模块一每句一次 $O(N d)$ 输出层；
- 模块二每步 $O(k d)$；
- 若 $L$ 较大，收益随 $L$ 增长而更明显；
- 训练时模块二的候选打包与 mask 是主要工程复杂度。

## 11. 评估方案

### 11.1 数据

建议覆盖三种任务形态：
- 对话（如 DailyDialog）：copy 通道收益明显；
- 摘要（如 CNN/DailyMail、LCSTS）：内容词由输入决定；
- 问答（如 SQuAD）：答案词常出现在输入中。

### 11.2 基线

1. 同参数量、同数据量的标准 Transformer LM；
2. 标准 LM + 每步 top-$k$ 采样（区分“每步截断”与“整句压缩词表”）；
3. 自适应 softmax（对比另一条降低输出层成本的路线）。

### 11.3 指标

| 类别 | 指标 |
| --- | --- |
| 覆盖率 | Recall@k、FullCoverageRate、$k$-覆盖率曲线 |
| 质量 | BLEU / ROUGE / EM / 任务准确率 |
| 语言建模 | 受限困惑度 |
| 效率 | 延迟、吞吐、输出层 FLOPs、显存 |
| 消融 | $k$、闭包、copy、候选噪声、联合训练 |

### 11.4 关键实验

- 覆盖率-加速比曲线：找到 $k$ 的拐点；
- 与基线在“同等延迟”下的质量对比；
- 不同输入长度下模块一的开销占比。

## 12. 局限与风险

1. **覆盖率不是 100%**：数字、专名、罕见词容易漏在 $C$ 外；v1 靠阈值与 copy 通道缓解，报告覆盖率为主要风险指标。
2. **模块一的语序损失**：模块一按集合建模，否定、指代、主宾关系在其预测阶段被丢弃，可能削弱覆盖率；模块二重读有序输入，生成阶段能恢复这些信息，但模块一的预测质量仍受集合表示限制。
3. **$k$ 预算固定**：长答案、枚举型答案需要更大 $k$，固定 $k$ 会顾此失彼；可行方向是按预测长度自适应。
4. **功能词占用预算**：闭包与虚词几乎必然出现，挤占内容词名额。
5. **两模块误差叠加**：模块一漏词时模块二无法补救，联合训练只能缓解。
6. **模块二容量**：小词表解码器对长程结构（如嵌套从句）的建模能力有限。
7. **分词粒度**：按词还是按 BPE；中文无空格，词边界本身需要约定。
8. **线性编码器的表达力**：线性注意力、SSM、窗口聚合在长距离精确依赖上弱于全量自注意力，是 2.4 的代价；关键任务可在短窗口内保留高精度注意力。

## 13. 相关工作

- **Copy / 指针生成网络**：允许生成时复制输入词，但输出层仍覆盖全词表（Gu et al., 2016; See et al., 2017）；本框架在全序列预测模式下把输入词并入压缩词表。
- **自适应 softmax**：用分层结构降低输出层成本（Grave et al., 2017），但解码仍逐词、搜索空间不变；本框架同时缩小输出层与搜索空间。
- **kNN-LM / RETRO**：从外部记忆或语料检索信息（Khandelwal et al., 2020; Borgeaud et al., 2022），解决“知识从哪来”；本框架解决“候选集多大”。
- **约束解码**：模块二正是“给定词表约束的生成”（Hokamp & Liu, 2017），只是约束由模块一动态给出。
- **Set2Seq**：集合到序列的建模（Vinyals et al., 2016），与本框架共享“无序输入 → 有序输出”的形式。
- **投机解码**：小模型起草、大模型验证（Leviathan et al., 2023），加速逐词生成；与本框架正交，可叠加。
- **非自回归 / 扩散语言模型**：并行生成，难点在顺序与一致性；本框架保留自回归但压缩词表。
- **掩码式生成 / 流匹配**：MaskGIT 式迭代采样与 Flow Matching 把生成建模为集合或连续分布（Chang et al., 2022; Lipman et al., 2023），本文第 6 章将二者列为模块一的可选算法。
- **循环一致性**：cycle consistency 让多个约束互相印证（Zhu et al., 2017）；第 8 章的三元组一致性借鉴了这一思想。
