# 文档规范

## 三种版本

### 简略说明版（`docs/简略说明版/`）

- 目的：用最短的篇幅说清想法是什么、解决什么问题、核心结构长什么样。
- 篇幅：一到两屏，尽量不超过 80 行。
- 内容：问题、一句话方案、模块划分、输入输出、关键指标、主要风险。
- 不写：推导细节、备选方案、完整代码。

### 扩展中途版（`docs/扩展中途版/`）

- 目的：展开推导、记录备选方案与取舍、规划实验，是「正在想」的工作稿。
- 篇幅：不限，允许结构松散、允许 TODO。
- 内容：动机推导、方案对比表、伪代码、指标与评测草案、风险、待定问题。
- 约定：标题下注明「建设中」，结论可能推翻；定稿后把结论沉淀到最终版，本文保留推演过程。

### 最终版（`docs/最终版/`）

- 目的：结论稳定，别人可以照着实现、自己可以照着复现。
- 篇幅：不限，通常最长。
- 内容：形式化定义、模块接口、结构、训练与推理、关键代码、评估方案、局限、相关工作、路线图。
- 约定：改动需要记录理由（文末「变更记录」）。

## 晋升流程

```
简略说明版 ──想清楚──▶ 扩展中途版 ──结论稳定──▶ 最终版
```

- 三份文档同名，放在三个文件夹下。
- 不允许只写最终版就跳过前两档；但允许某一档长期停留在「草稿」状态。

## 头部模板

```markdown
# 想法名称（版本名）

> 状态：草稿 / 建设中 / 稳定 v1.0 · 最后更新：YYYY-MM-DD
> 关联：[简略说明版](../简略说明版/想法名称.md) · [扩展中途版](../扩展中途版/想法名称.md) · [最终版](../最终版/想法名称.md)
```

## 命名

- 文件名使用中文想法名，不加日期前缀；日期写在文档头部。
- 同一想法三份文档文件名保持一致。
- 代码块统一用围栏代码块并标注语言；中文注释。
